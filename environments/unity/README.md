# Experimental Unity camera adapter

This is integration research, **not an admitted leaderboard task**. The official ML-Agents 1.1.0 Mac example runs under Rosetta on the tested Apple Silicon Mac. `assets.json` pins both the archive and the extracted input tree. Profiler timer files generated by Unity are excluded from the input digest.

Install a separate Intel Python 3.10.12 environment, then the pinned dependencies and official application:

```sh
uv python install cpython-3.10.12-macos-x86_64-none
uv venv --python cpython-3.10.12-macos-x86_64-none .game-envs/unity
uv pip install --python .game-envs/unity/bin/python -r environments/unity/requirements.lock
uv run python environments/unity/install.py
```

The experimental `generalgamebench.unity_engine.UnityPixelsEnv` helper loads VisualFoodCollector, selects one player, passes through its native 84×84 RGB camera and gives all peers no-op actions. Private vectors, IDs, rewards and masks are never part of a participant observation. Eight discrete controls map to the native continuous movement and binary fire controls. This helper is not registered in the production runner.

Two independent processes reproduced all 129 frames of a 128-action sequence exactly on this Mac. A separate straight-line probe observed a negative-food reward. Positive-food collection and a complete scored task contract remain unverified. These probes do not establish a ranked Unity environment or support for arbitrary Unity games.

The executable remains a separately downloaded third-party asset. Its source is the official Unity ML-Agents example bundle; see [integration diagnostics](../../docs/INTEGRATION_ATTEMPTS.md).
